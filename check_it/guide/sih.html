Honest risks — and the plan for each

Technical risks

  • LLM hallucination → evidence-only prompts, strict schemas, deterministic core
  • Weak embedding matches → 0.65 threshold + review queue
  • Data quality → schema validation + normalization + edge-case tests

Project risks

  • Scope creep → levels gated; Level 3 explicitly out of scope
  • Over-claiming → every claim labeled verified/assumed/unknown
  • Team on-ramp → first-7-days plan with bite-sized tasks
Demo risk: the demo uses synthetic data — we say so. Real deployment needs DPDP-compliant data; this is presented as the honest next step, not hidden.

Likely judge questions — prepared answers

QuestionAnswer
Where is the real data?Synthetic, with known ground truth — deliberate for development; real usage follows DPDP consent
Why not use an LLM for everything?Deterministic core is auditable and works offline; LLM explains but never decides
How is this different from Saral/VSK?They capture marks and admin views; we analyze error patterns per concept over time
What about teacher resistance?We save the teacher time (30 sec → insights) and keep them in control (approval gates)
Can it generalize to other states/languages?Embedding mapping + i18n keys + multilingual models; honest about language support
What does success look like in a pilot?FLN attainment improvement with measurable before/after evidence per concept
