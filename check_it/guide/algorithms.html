Part 05 · Core Algorithms

A deterministic, evidence-first algorithm

The detection engine is deliberately not a black box. Identical input always yields identical output, and every decision can be traced to its evidence.

Mistake detection pipeline

1. Validate & normalize      → clean answers, structure checks
2. Extract concepts          → explicit metadata OR embedding mapping
3. Extract error types       → rule-based taxonomy (20 types)
   e.g. wrong_common_denominator, sign_error, area_perimeter_confusion
4. Compute repeated errors   → same error across ≥2 assessments
5. Confidence scoring        → Wilson lower bound × recency weight
6. Flag learning gaps        → total_errors ≥ 3 AND assessments ≥ 2
                             AND confidence ≥ 0.70
7. Preserve uncertainty      → low evidence → "Insufficient data", never a guess

The fingerprinting algorithm in detail

conf = min(0.95,
            wilson_lower_bound(error_rate, n) * 1.2 * recency_weight)

  error_rate      = error_count / responses_for_concept
  n               = number of responses observed
  recency_weight  = 1.0 for assessments within 6 weeks,
                    0.85 within 12 weeks, else 0.70

Gap flags (recurring):
  total_errors        ≥ 3
  assessments_flagged ≥ 2
  confidence          ≥ 0.70

The Wilson lower bound is the conservative edge of the observed error rate — honest under small samples; the 0.95 ceiling prevents false certainty.

Boundaries: single-assessment findings are reported as "initial indication — reassess", never as a confirmed gap.

From evidence to action — then prove it worked

1 · Choose intervention

Teacher selects from recommendations by gap type (e.g. denominator handling → equivalent-fractions mini-lesson + 5 targeted problems).

2 · Create & assign

LLM drafts the worksheet (evidence-constrained); teacher reviews, edits, assigns. Nothing ships without teacher approval.

3 · Reassess & compare

improved  → post_rate < 0.20 AND p < 0.05
worsened  → post_rate ≥ pre_rate
persisted → otherwise

4 · Close or iterate

"Gap closed" is recorded with before/after evidence. If persisted, the teacher adjusts the approach — never blames the student.

Four screens, four decisions — no decorative charts

1 · Overview

RAG status + KPI chips: high-frequency gaps, confidence trend.

Decision: what needs attention this week?

2 · Heatmap

Class × concept error density; toggles to gap confidence.

Decision: which concepts for the whole class?

3 · Student Profile

Timeline, concept radar, error-type table, every row cites evidence.

Decision: what does this student need?

4 · Insights

LLM explanation + cite; school/class/cohort drill-down.

Decision: what intervention, with what confidence?

The interaction rules behind the screens

RuleDetail
No data → guidanceEmpty states explain the next step ("Upload Term 1 CSVs to begin") instead of blank screens
Evidence always visibleConfidence badge + question IDs beside every finding; click → drill-down
Fuzzy → explicitDrill-down offers "Exact match" and "Similar" views so teachers see how a concept was matched
Approval gateInterventions are drafts until the teacher approves them
Print/exportEvery view exports a clean report for SMC/SMDC or parent meetings
Result: a teacher trusts the tool because they can always see why it says something — and can always overrule it.
