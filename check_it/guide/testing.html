Prove the system works — not just that it runs

A learning-gap detector must be measured against ground truth. We define the testing bar before writing the first feature.

Testing strategy

LayerWhat is testedTool

Target bar: recall ≥ 0.85 and precision ≥ 0.80 on planted-error synthetic data before SIH; every metric displayed with the numbers, not adjectives.

Tested edge cases — because the demo will hit them

Data edge cases

  • Duplicate student IDs
  • Empty / all-correct / all-wrong answer files
  • Question ID not in bank
  • Non-standard answer strings
  • Concept mismatch (embedding low confidence)

Behavior edge cases

  • Single assessment (fewer than 2 → "initial indication")
  • Errors below threshold → shown but not flagged
  • LLM down / offline → rule-based flow still works
  • Teacher approves then rejects intervention → clean states
Honesty rule: every edge case has a defined output; "insufficient data" is a first-class result, never a crash or a guess.

50 → 50K students: where scaling actually bites

What scales cheaply

  • Rule-based detection — pure compute, cacheable
  • Embedding concept mapping — batchable, model is tiny
  • SQLite → PostgreSQL — schema already normal-form

What needs care

  • LLM calls — batch/queue, cache identical prompts
  • Heatmap rendering — pre-aggregate, don't compute live
  • Offline sync conflicts — last-write-wins + audit log
Offline-first (post-SIH): Service Worker caches app + quantized model (~20 MB) + question bank; IndexedDB holds local data; Background Sync flushes uploads and LLM jobs when online. Multilingual via i18n JSON + per-question translations + model-supported languages only.
