Part 03 · Technical Architecture

Three levels — build in order, never skip ahead

The project is scoped in three build levels. Each level has a reason to exist, a clear outcome, and deliberately excludes tools that don't help yet.

Level 1 — MVP Weeks 1–4

CSV upload → Pandas → mistake detection → concept heatmaps → Streamlit dashboard.

Python + Pandas + Streamlit + Plotly + MiniLM embeddings. No database.

Level 2 — SIH Prototype Weeks 5–8

Adds SQLite, multi-assessment tracking, student profiles, LLM explanations, intervention engine, PDF reports.

Persistence + AI + the closed feedback loop.

Level 3 — Production Post-SIH

FastAPI + PostgreSQL/TimescaleDB + auth + React PWA + offline-first + monitoring.

Scalable, secure, multilingual, deployable at district/state scale.

MVP → validate with real teachers → SIH prototype → then design production. Never build Level 3 first.

What is NOT in the stack — and why

Excluded from MVP/SIH

  • Docker / Kubernetes — no benefit at prototype scale; adds real complexity
  • React / Node — Streamlit delivers the demo with zero frontend code
  • Heavy ML / deep learning — deterministic rules + statistics are more auditable and sufficient
  • PostgreSQL — SQLite covers prototype needs; upgrade only when scaling

Rule: every technology must have a reason

Each tool maps to a concrete job: Pandas reads data, Streamlit shows it, embeddings map concepts, LLM explains, SQLite remembers. No tool is included for its name.

This keeps the project beginner-buildable and the demo honest — "actually impressive because it works."
