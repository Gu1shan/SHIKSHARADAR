PART 1Executive Summary

Shiksha Radar is an AI-powered early learning-support platform that helps teachers identify which specific concepts students struggle with, why (evidence from repeated error patterns), and what targeted intervention might help — before learning gaps become learning failures.

The core insight: Two students scoring 60% may have completely different learning needs. Student A struggles with fractions (denominator errors across 3 assessments). Student B struggles with algebra (sign errors) and geometry. A marks dashboard shows them as identical. Shiksha Radar shows the teacher the difference.

Why This Fits SIH

  • Addresses NIPUN Bharat (foundational literacy & numeracy by Grade 3, by 2026–27).
  • Aligns with NDEAR building blocks (Saral assessment input, VSK-style analytics output).
  • Solves a real teacher pain point: concept-level insight vs. marks-only dashboards.
  • Uses explainable AI responsibly — deterministic core + guarded LLM layer.

The Remaining Gap

What exists: census data (UDISE+), content (DIKSHA), marks scanning (Saral), governance dashboards (VSK), commercial adaptive practice.

What it does well: massive-scale collection, content distribution, aggregate monitoring, adaptive practice.

The gap: no system converts raw assessment answers into longitudinal concept-level error-pattern intelligence that a classroom teacher can act on — with evidence, confidence, and a closed intervention → reassessment loop.

Shiksha Radar is different because it is: concept-granular · error-type-specific · longitudinal · evidence-cited with confidence scores · teacher-facing (not admin-facing) · intervention-loop-closed · privacy-first by design.

PART 4Innovation — What Is Novel

Mistake Fingerprinting (Core Innovation)

A longitudinal, multi-assessment error-pattern profile per student per concept, decomposed by error type, with recurrence tracking, trend analysis, and calibrated confidence.

Traditional:  "Student scored 60% on Fractions"
Shiksha Radar: "Fractions → 7 errors across 3 assessments (84% confidence)
                ├─ Denominator handling: 5 errors (recurring, ↑ trend)
                ├─ Simplification: 1 error (isolated)
                └─ Addition: 1 error (careless)
                → Recommended: Equivalent fractions review + 5 targeted denominator problems"

Evidence-Based Intervention Loop

Detect (concept + error type + confidence)
    ↓
Recommend (specific remediation + practice set)
    ↓
Teacher assigns / Student practices
    ↓
Reassess (same concept, comparable difficulty)
    ↓
Compare (pre vs post error frequency)
    ↓
"Gap closed" or "Persisted: needs different approach"

Explainable-by-Design AI

  • Deterministic core: mistake detection, concept mapping, aggregation = rules + statistics (auditable).
  • LLM only for: natural-language explanation of structured evidence, practice generation, translation.
  • LLM never: decides "weak student," assigns risk scores, replaces teacher judgment.

Privacy-First Architecture

  • Pseudonymized IDs (Student_001) in the prototype.
  • No PII in the analytics pipeline.
  • DPDP Act 2023 compliant: verifiable parental consent (production), data minimization, purpose limitation, no behavioral tracking/advertising.

LLM Integration Architecture (Hallucination-Resistant)

Structured Evidence (JSON) → Prompt Template → LLM → Teacher-Friendly Output
                                    ↓
                            GUARDRAILS
                            • No student names
                            • No predictions
                            • Cite evidence
                            • Confidence range
                            • "May benefit" not "will fail"

Evidence JSON (no PII, structured, verifiable)

{
  "student_id": "Student_001",
  "concept": "Fractions - Denominator Handling",
  "total_errors": 7,
  "assessments_analyzed": 3,
  "error_breakdown": {"denominator": 5, "simplification": 1, "addition": 1},
  "trend": "increasing",
  "confidence": 0.84,
  "recent_assessment_date": "2025-01-15"
}

How to Reduce Hallucinations

  1. Ground every claim in evidence — LLM only sees structured JSON from the deterministic engine.
  2. Constrain output format — template with placeholders, validated after generation.
  3. Forbidden-label + missing-evidence validator blocks non-compliant output.
  4. Low temperature (0.2–0.3) for explanation tasks.
  5. Fallback chain — if LLM fails/times out, use template-based explanation (always available).
  6. Never feed PII — LLM receives only pseudonymized IDs and structured stats.

PART 9Mistake Fingerprinting Engine

Error Taxonomy (Mathematics — Extensible)

CategoryError Types
Conceptualmisconception, wrong_approach, formula_selection
Proceduraldenominator_handling, sign_error, simplification, carry_borrow, decimal_placement, unit_conversion
Calculationarithmetic, multiplication_fact, division_fact
Carelessincomplete, misread, copy_error, transcription
Unknownambiguous, blank

MVP Pipeline (Deterministic, Transparent)

1. Load & validate CSV (schema, types, IDs, duplicates)
2. Normalize answers (lowercase, strip, unicode-normalize)
3. Score: exact match after normalization
4. Classify errors via rule-based keyword/regex per error type
5. Map question → concept (rule lookup → embedding fallback → teacher-review flag)
6. Aggregate per student × concept over time:
   - Error frequency (count, rate)
   - Recurrence (assessments with errors)
   - Trend (slope of error rate across assessments)
   - Confidence (Wilson score interval × recency weight, capped at 0.95)
7. Detect learning gaps via thresholds:
   total_errors ≥ 3 AND assessments_with_errors ≥ 2 AND confidence ≥ 0.70
8. Output: LearningGap(student, concept, dominant_error, evidence_count,
                       assessments, confidence, trend)
Confidence formula (conceptual)
Confidence = min(0.95, Wilson_lower_bound(error_rate, n) × 1.2 × recency_weight)
Wilson score interval = statistically sound confidence for a proportion, avoids over-confidence on small samples. Recency weight = recent errors count more. Capped at 0.95 — never claims certainty.

Advanced Version (Research-Grade — NOT for MVP)

TechniquePurposeComplexityWhen to Add
Bayesian Knowledge Tracing (BKT)Model latent knowledge state per conceptMediumPost-SIH; needs sequential data
Deep Knowledge Tracing (DKT/LSTM)Complex temporal dependenciesHighResearch project; 10K+ sequences

Recommendation
Build MVP with deterministic rules + statistical confidence. Add BKT only if you have longitudinal data (10+ assessments/student) and want a research paper.

PART 10Concept Mapping

Three-Tier Approach

Question → Rule lookup (exact ID match) → Found? → Use rule
                    ↓ No
         Embedding similarity → Confidence ≥ 0.65? → Use embedding
                    ↓ No
         Flag for teacher review → "Unmapped question"

Rule-Based (MVP — start here)

questions.csv carries question_id → concept, sub_concept columns.

  • 100% accurate for curated question banks
  • Zero compute; fully auditable
  • Con: manual maintenance; doesn't handle unseen questions

Embedding-Enhanced (SIH prototype)

Model: paraphrase-MiniLM-L6-v2 (384-dim, 80MB, CPU, Apache 2.0).

  1. Pre-compute concept embeddings from concept descriptions
  2. Encode question text → vector
  3. Cosine similarity vs each concept description
  4. Best match ≥ 0.65 → mapped; else "Unknown / flag for review"

Embeddings Explained Simply

  • Embedding: converting text into a vector of numbers that captures meaning — similar texts get similar vectors.
  • Vector similarity: cosine similarity measures how aligned two vectors are (1 = identical meaning, 0 = unrelated).
  • Why useful: the model has "read" lots of language, so it knows "simplify" ≈ "reduce" in math contexts.
  • Multilingual option: paraphrase-multilingual-MiniLM-L12-v2 supports Hindi/Telugu/Tamil/Bengali/Marathi (420MB, still CPU-friendly).
  • When rules are better: rules are deterministic and auditable for a known question bank; embeddings add flexibility for open-ended import.

Recommendation Logic (Conceptual)

LearningGap(student, concept, dominant_error, evidence_count, assessments, confidence, trend)
    ↓
Intervention:
  - concept, dominant_error
  - evidence_summary ("7 errors across 3 assessments")
  - confidence (from gap)
  - steps (3–4): conceptual → procedural → practice → metacognitive
  - practice_questions (5 targeted)
  - reassessment_plan (when, how many, success criteria)
ConceptErrorSample Intervention Steps
Fractionsdenominator_handlingReview equivalent fractions with visual models → Practice common denominators (5 guided) → 5 targeted worksheet problems
FractionssimplificationReview GCF + simplification rules → Practice simplifying 10 fractions with step feedback
Algebrasign_errorReview integer rules (neg × neg = pos) → 10 sign-focused problems with error highlighting
Algebraformula_selectionCreate a formula decision flowchart → Practice identifying equation type before solving
Geometryarea_perimeter_confusionVisual contrast area vs perimeter → 5 mixed problems with labelled diagrams

LLM-Enhanced Generation (SIH Prototype)

LLM receives the same structured evidence JSON and returns: explanation (2–3 sentences), steps (3–4 with type tags), practice_questions (5 with answers), reassessment_plan. Output is parsed and validated — structure checked, forbidden labels blocked, evidence cited.

Feedback Loop Tracking (The Core Product Feature)

close_loop():
  → filter reassessment responses for same student + concept + sub_concept
  → compute pre_error_rate, post_error_rate
  → proportion z-test (simplified statistical test)
  → outcome:
      improved  → post_rate < 0.20 AND p < 0.05
      worsened  → post_rate ≥ pre_rate
      persisted → otherwise
  → store {pre_rate, post_rate, p_value}
Why the loop matters
This detect → intervene → reassess → compare cycle is a major product differentiator and the central demo story.

Synthetic Data Strategy (Primary for MVP/SIH)

Design principles: NCERT Class 3–8 Mathematics alignment (NIPUN Bharat focus) · realistic error patterns from math-education research · longitudinal (5–8 assessments per year) · diverse archetypes · no PII.

ArchetypePattern
Student AFractions difficulty (denominator-dominant errors only in Fractions)
Student BAlgebra difficulty (sign errors + formula selection)
Student CRandom mistakes (moderate error rate everywhere, no clear pattern)
Student DImproving over time (error rate decays across assessments)
Student EPersistent difficulties (high error rate across all concepts, stable)
Student FOn track (low error rate everywhere)

Generation Plan (Conceptual)

  1. Build NCERT-aligned concept hierarchy: Fractions (denominator_handling, simplification, addition, subtraction, multiplication, comparison), Decimals, Algebra, Geometry, Measurement, Data Handling.
  2. Generate a question bank: ~3 questions × 3 difficulty levels per sub-concept.
  3. Assign archetype per student; compute per-concept error probability from the archetype.
  4. For each assessment (6–8 per student): sample ~20 questions stratified by concept; mark correct/error by probability; on error, pick an error type from the concept's error-pattern distribution and distort the answer.
  5. Timestamps spread over the academic year (Jul–Feb).
  6. Output files: students.csv, questions.csv, responses.csv, concept_map.csv.

Scale: 50 students × 6 assessments × 20 questions ≈ 6,000 response rows — small enough for a beginner, rich enough for a compelling demo.

Honest caveat

Implementation Approach

  • UI i18n: locale JSON files (en.json, hi.json, ...) + a session-state language toggle.
  • LLM multilingual: prompt in English → request output in target language → back-translation sanity check (optional).
  • Embedding swap: English-only (MiniLM-L6-v2, 80MB) for MVP; multilingual (MiniLM-L12-v2, 420MB) for SIH; both CPU-friendly.

Likely Judge Questions

QuestionAnswer
"How is this different from an Excel marks sheet?"Excel shows scores; Shiksha Radar shows concept × error-type × trend × confidence across assessments — plus a closed intervention loop.
"How do you know the concept mapping is correct?"Rule-based for the question bank (100%); embedding fallback ≥90% on labeled set; unknowns flagged for teacher review.
"What about careless students?"Careless errors are a separate taxonomy category; gap detection requires recurrence across ≥2 assessments.
"How will this work without internet in a village?"Offline-first design: local CSV + rules + cached embeddings + template interventions; LLM only when online.
"What is your privacy story for minors?"DPDP Act 2023: pseudonymized IDs, no PII, verifiable parental consent in production, data minimization, 2-year retention.
"Why not use an LLM to grade everything?"LLMs are unreliable and non-reproducible for deterministic grading; rules for detection, LLMs only for teacher-facing explanation.
