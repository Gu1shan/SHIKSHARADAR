Real data, synthetic data, and the DPDP Act — privacy by design

Data Reality

The data problem — and the synthetic-data solution

Real-world data reality

  • No open, structured answer-level datasets exist for Indian schools
  • Existing systems (Saral) hold marks, not error patterns
  • Raw student data is protected — we must not use it to train

Our approach

  • Synthetic data generator reproducing classroom archetypes
  • Six archetypes: Strong · Gaps-small · Gaps-large · Recurring-error · Careless-inconsistent · Needs-support
  • 4 CSV files (students, assessments, answers, questions) with planted, known error patterns
  • Lets us measure detection accuracy because ground truth is known
Honest framing: synthetic data is for development and demo. Real usage follows anonymized, consent-based data under DPDP; we say so rather than claim real data we don't have.

Responsible AI

Child-safety safeguards

Technical safeguards

  • Pseudonymization: Student_001, never real names in outputs
  • PII never sent to LLM — only structured, pseudonymized evidence
  • No real names on dashboards — pseudonyms + teacher-controlled unlock
  • Deterministic core: core analytics works fully offline without any LLM

Language & ethics safeguards

  • Approved vocabulary: "possible learning gap", "may benefit from additional support"
  • Never "weak", "bad", "failing", "at risk"
  • Findings shown as confidence-scored hypotheses, reviewable
  • No ethnicity / income / locale features in detection
Non-negotiable: this is a decision-support tool for teachers — it never labels, ranks, or predicts a child's future.
